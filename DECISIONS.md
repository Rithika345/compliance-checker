- Known limitation (Stage 2): app/extract.py's content sniffing cannot actually reject arbitrary binary garbage that isn't a PDF or a DOCX zip. DESIGN_PLAN's rule is "decode as UTF-8, fall back to latin-1, then reject" -- but latin-1 is a total mapping over all 256 byte values, so it never raises UnicodeDecodeError, making the "reject" branch unreachable dead code in any correct implementation of that rule, not just mine. Verified this directly with os.urandom(500).decode("latin-1"), which succeeds. Downstream, the 200-char minimum and then retrieval's no-match gate still catch nonsense content in practice, just less cleanly than an explicit "unrecognized file type" rejection. Discussed with Rithika; left as-is (not in Stage 2's task list), to note in the README's known limitations at Stage 6.
